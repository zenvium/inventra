# Export one structure

One subdomain becomes one object in the requested output format. Do not change the product files. More than one subdomain is [Export many sheets](export-many-sheets.md). Stop and open that page.

1. Open the mongoose schema and `<Subdomain>Props`, then each nested props interface. The paths are in [field-edits.md](../field-edits.md) under "Find the files". The collection name is the mongoose `collection` option. Root `_id` and root `schemaVersion` come from that model, which extends `MongooseSeedwork.Base`. They are the first property rows. `schemaVersionDataType` uses that path's `required` and `default`. Do not take `_id` from the aggregate. Export the full schema tree in path order. Include every nested path. An array without `_id: false` is an entity block. `NestedPathOptions` is a value block. Do not stop at the root scalars.
2. Fill the rows from the prop table in [field-types.md](../field-types.md) under "From code back to rows". Use [sheet-layout.md](../sheet-layout.md) for workbook output, or [text-format.md](../text-format.md) for plain-text output.
3. For plain-text output, emit the Markdown outline defined in [text-format.md](../text-format.md), with context, subdomain, collection, and all fields; return it to the user unless they requested a file. For workbook output, a parent that is writing the workbook tells you to return the document and not write the file. Otherwise follow [excel/write.md](../excel/write.md). The only file is `<identifier>-system-design-details-output.xlsx` at the repo root. `<identifier>` is `<scope>` from [file-tree.md](../file-tree.md) with the leading `@` removed. Do not invent a product name. Copy `access` from a prior workbook read when role letters have to be kept. Leave them blank otherwise. Do not invent `C` `R` `U` `X`.
